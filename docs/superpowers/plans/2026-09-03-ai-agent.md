# AI Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer a customer on WhatsApp from the knowledge base and nothing else, move the lead along the funnel while answering, and hand off to a person the moment it cannot do that honestly.

**Architecture:** One turn is built fresh from the database, sent to a model on OpenRouter as a request for one JSON object, validated with Zod, and applied through the same code paths an operator uses. The client is an interface the tests replace; nothing reaches the network in a test. The turn runs inside the inbound queue, after Meta has already been answered, so a slow model cannot make Meta retry.

**Tech Stack:** Fastify 5, Drizzle ORM 0.45 + drizzle-kit, PostgreSQL 17, Zod 4, Vitest 4 · React 18, Vite 5.

**Spec:** [`docs/superpowers/specs/2026-09-03-ai-agent-design.md`](../specs/2026-09-03-ai-agent-design.md)

## Global Constraints

- **Language.** Code, comments, commit messages and docs in English. Every string a user reads stays Russian. What the AGENT says to a customer is neither: it answers in the customer's language, and the instructions that tell it so are the owner's own text.
- **Commands run from the repository root:** `npm --prefix server …`, `npm --prefix rakurs …`.
- **Server tests need a database.** Each agent is given its own through `TEST_DATABASE_URL`; a concurrent run on a shared one deadlocks the suite.
- **No test may reach the network.** The OpenRouter client is an interface; tests inject a fake. So is the Graph client, already.
- **An API key never reaches a response, a log or a column in plain text.** It follows the WhatsApp token's path: `encryptSecret` with the credentials key, and `withoutSecret` on anything an error carries.
- **Role vocabulary:** `owner` and `member`. Editing the instructions, the model and the key is owner-only. Turning the agent off for one conversation is open to any member — the operator who is watching it go wrong is the one who has to stop it.
- **An agent or a record the caller does not belong to answers 404, never 403.**
- **The agent answers only from what retrieval gave it.** Every prompt says so, and every path that finds nothing hands off rather than inventing.
- **Nothing the agent does bypasses the rules stage 3 wrote.** A stage move goes through the same code an operator's move does, fires the same auto-message, and records `ai` rather than `operator`.

## Definition of done

- An inbound message on an enabled agent produces a reply, sent through WhatsApp and stored with the knowledge records it was built from.
- No reply is sent when the agent is off, when someone has taken the conversation, when the window is closed, or when the last message was ours.
- A reply that is not valid JSON is retried once and then hands off.
- A stage the model names that does not belong to this agent is refused; unknown field ids are dropped; a stage move fires the same auto-message an operator's move does and records `ai`.
- A handoff turns the agent off for that conversation and leaves a note saying why.
- The owner can change the model, see what a turn cost, and try instructions in a sandbox that sends nothing.
- The API key is never returned, logged, or stored in plain text.
- No test reaches the network.
