# Meta Conversions API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tell Meta which of its ads produced a sale, so the optimiser buys more of the people who pay rather than more of the people who open WhatsApp.

**Architecture:** An order marked paid on a conversation that came from a Click-to-WhatsApp ad queues one event. The queue is drained by the pass that already drains WhatsApp events, so Meta being down never fails an operator's action. Every event carries an `event_id` derived from what it reports, so a retry, a redelivery and a resend by hand all count once.

**Tech Stack:** Fastify 5, Drizzle ORM 0.45 + drizzle-kit, PostgreSQL 17, Zod 4, Vitest 4, Node's crypto and fetch · React 18, Vite 5.

**Spec:** [`docs/superpowers/specs/2026-09-03-meta-capi-design.md`](../specs/2026-09-03-meta-capi-design.md)

## Global Constraints

- **Language.** Code, comments, commit messages and docs in English. Every string a user reads stays Russian.
- **Commands run from the repository root:** `npm --prefix server …`, `npm --prefix rakurs …`.
- **Each agent gets its own test database** through `TEST_DATABASE_URL`; a shared one deadlocks when two runs overlap.
- **No test may reach the network.** The Meta client is an interface; tests inject a fake, exactly as the Graph client and the model client are.
- **The access token never reaches a response, a log, or a stored error.** It is encrypted with the credentials key, sealed to the agent's id the way stage 5 seals the OpenRouter key, and every error passes through `withoutSecret` from `server/src/lib/whatsapp/graph.ts`.
- **Only a conversation carrying `ctwa_clid` is ever reported.** Meta cannot attribute anything else, and inventing an attribution would corrupt the optimiser the client is paying for.
- **`event_time` is when the thing happened,** not when we send. A week-old sale reported with today's timestamp lands in the wrong attribution window.
- **Nothing about the customer is sent beyond the click and the hashed phone.** Not their name, not their messages, not what they asked.
- **Role vocabulary:** `owner` and `member`. Configuring the dataset is owner-only; resending one event by hand is open to any member, because the operator watching a failed report is the one who notices.
- **An agent or a record the caller does not belong to answers 404, never 403.**

## Definition of done

- An order marked paid on an ad-sourced conversation queues exactly one purchase, carrying the order's amount, its currency, and the time it was paid.
- An order on a conversation with no `ctwa_clid` queues nothing, and the lead card says why.
- Marking the same order paid twice queues one event.
- A lead reaching a qualified stage queues one lead event, once.
- The queue sends, records what Meta answered, retries a refusal to the cap and then stops.
- A token never appears in a stored error or a response.
- An owner can configure the dataset, see the last events with their status, and resend one.
- No test reaches the network.
