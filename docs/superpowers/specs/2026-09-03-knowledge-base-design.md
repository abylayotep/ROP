# The knowledge base

**Date:** 2026-09-03
**Status:** Approved. Ready for implementation planning.
**Stage:** 4 of 7 in the pleep-model rebuild. Builds on
[orders and the funnel](2026-09-03-orders-funnel-design.md).

## Goal

Give the agent something to answer from. A per-agent store of short, quotable facts —
products, questions and answers, procedures, contacts — that stage 5 searches before it
writes a reply, and that a person can read, correct and add to without waiting for anyone.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Retrieval | Postgres full-text search, Russian configuration | No test may reach the network, and embeddings need a vendor. OpenRouter — the one the owner is choosing models from in stage 5 — has no embeddings endpoint, so committing to vectors now means a second provider before the agent exists. Postgres finds «доставка в Астану» in a delivery procedure today, for nothing, offline, in a test. |
| Room for vectors | The searchable text is its own column, and search is one function behind one signature | Stage 5 or 6 adds an embedding column and a second ranker without touching a route or a screen. |
| The unit of knowledge | One row is one retrievable answer | A document split into chunks at import time and a hand-written item are the same thing to the agent. Two tables for that would mean two search paths and two ways to be stale. |
| Imports | Pasted text and a fetched web page | These are what a Kazakhstan seller can hand over in a minute. A PDF price list needs a parser, a licence and a failure mode of its own, and nobody has asked for one yet. |
| Files | Not in this stage | pleep attaches images to items so its agent can send the right photo. That is worth having, and it belongs with the agent that would send them. |
| Editing an imported item | Allowed, and it survives a reimport | An owner who fixes a price the crawler misread must not lose the fix the next time the page is fetched. |

## Data model

Migration `0006`:

```
kb_sources   id, agent_id fk→agents cascade, kind text, title text,
             url text, status text, error text, item_count integer default 0,
             created_at, imported_at
             index(agent_id, created_at)
kb_items     id, agent_id fk→agents cascade,
             source_id fk→kb_sources set null,
             kind text, title text, content text,
             edited boolean not null default false,
             created_at, updated_at
             index(agent_id, kind)
             generated tsvector column over title and content, GIN indexed
```

`kb_sources.kind` is `text` or `page`. `kb_sources.status` is `pending`, `ready` or `failed`.
`kb_items.kind` is `product`, `qa`, `procedure`, `contact` or `other`.

`source_id` is nullable and set null on delete: an item written by hand has no source, and
deleting an import must not delete the corrections someone made to what it produced.

`edited` marks an item a person has changed. A reimport of the same source replaces the
items it produced, except those — a price the owner corrected by hand outranks the page it
came from.

## Search

One function, one signature:

```
searchKnowledge(db, agentId, query, limit) → { item, rank }[]
```

It builds a `websearch_to_tsquery` in the `russian` configuration, ranks with `ts_rank_cd`
over the generated column, and returns the best matches. A query that matches nothing
returns nothing — the agent in stage 5 is meant to say it cannot answer rather than
invent, and an empty result is how it learns that.

The column is generated by Postgres rather than written by us, so an item edited through
any path is indexed correctly by definition.

The Russian configuration stems Russian and folds case. It does not stem Kazakh; a
Kazakh-language knowledge base will match on exact words. That is a real limit, and it is
better than the English default, which stems neither.

## Imports

**Pasted text.** The owner pastes a block and says what kind of items it holds. It is split
on blank lines into items, each taking its first line as the title and the rest as the
content. A block with no blank lines is one item.

**A web page.** The server fetches the URL, strips scripts, styles, navigation and footers,
converts the rest to text, and splits it on headings. Each heading becomes an item title
and the text under it the content. A page with no headings is one item.

Both run inside the request and answer with what they made, so the owner sees the result
and can fix it immediately. A fetch that fails leaves the source with `status = 'failed'`
and its reason, in Russian, and creates no items.

The fetch is the only outbound HTTP on this stage. It takes the same deadline as the Graph
client, refuses anything that is not `http` or `https`, refuses a response that is not
HTML, and caps what it reads — a URL an owner pastes is not a URL we trust.

## Screens

**База знаний** replaces its placeholder: a list of items with a tab per kind and a search
box that uses the same endpoint the agent will, so an owner can see exactly what the agent
would find. Adding, editing and deleting an item is inline. Importing opens a panel with
the two inputs — a text area and a URL — and reports what it created.

An item shows where it came from. An edited one says so, because that is what a reimport
will preserve.

## Testing

Covered on the server: an item is found by a word from its content and by a stemmed form of
it; a query matching nothing returns nothing; an item belonging to another agent is never
returned and answers 404 by id; splitting a pasted block produces the items the operator
expects and one item when there is nothing to split; a page's headings become titles; a
reimport replaces what it made and keeps what a person edited; a URL that is not HTTP, is
not HTML, or never answers is refused with a Russian reason and creates nothing.

No test reaches the network: the fetch goes through an interface the tests replace, the
same way the Graph client is.

## Out of scope

Uploading PDF, DOCX or spreadsheets; images on items; crawling a whole site rather than one
page; embeddings; the agent that reads any of this, which is stage 5.
