# WhatsApp Connection 428 Investigation

Date: 2026-09-12 (Asia/Almaty).

## Reproduction

- Production stored `linked_state=open`, but had zero conversations and messages.
- Lifecycle logs showed 12 failed reconnect attempts, followed by stopped retries.
- The lifecycle deliberately retained the stored pairing status; the numbers API did
  not consult the live registry. Therefore `open` was not evidence of connectivity.
- Added allowlisted connection logs: number UUID, numeric disconnect status, and
  logged-out boolean only. No raw errors, frames, QR values, credentials, or messages.
- A diagnostic API rollout showed repeated `428` closes within a second of startup,
  without any successful open event.
- HTTP and anonymous WebSocket upgrades from the same API container succeeded.

## Controlled comparison

Two anonymous Baileys sessions used temporary in-memory credentials, with no access to
the stored production pairing. Neither QR content nor key material was printed.

| Profile | Full-history request | Result |
| --- | --- | --- |
| `Browsers.macOS('Ракурс')` | true | 428 after the registration payload |
| `Browsers.ubuntu('Chrome')` | true | QR available |

The profile was the only changed connection option. This isolates the native desktop
subplatform as the immediate connection failure, not the database or the UI.
An independent upstream report describes the same rejection:
[Baileys issue 2677](https://github.com/WhiskeySockets/Baileys/issues/2677).

The earlier desktop-profile change (`1a58c5c`) was incompatible with the live service.
The byte-restoration correction (`c083d8b`) remains independently regression-tested.

## Correction and verification

- Use the web-compatible Ubuntu/Chrome profile, retaining `syncFullHistory=true`.
- Test the actual login payload generated by the pinned Baileys implementation:
  `WEB_BROWSER` is required; native `DARWIN` previously failed the test (3 versus 0).
- Numeric disconnect metadata is tested without exposing raw upstream error details.
- Typecheck, build, and 108 linked WhatsApp tests across 10 files passed.
- Existing credentials and database rows are preserved; no logout or QR reset.
- API-only rollout completed with healthy HTTP checks. Production emitted a genuine
  `linked: connection open` at `2026-09-12T01:12:49Z` on the original saved pairing.
  Running image: `sha256:b1e3070afe7dc89471be64e1ca06845d304f660c128ab271a931384c35f50519`.
  No subsequent close events or container restarts were observed during follow-up.
- At `01:13:19Z`, stored conversations and messages remained zero. A fresh inbound test
  was requested from the owner; message delivery and historical import are not yet
  claimed. Saved sync metadata still reports zero history notifications and sync counter.
- Full server regression suite passed: 96 files, 1,308 tests, exit 0, 202.17 seconds,
  against the dedicated local test database. The 108-test linked gate passed before rollout.
