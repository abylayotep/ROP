# Ракурс — фронтенд

Кабинет продаж: одна компания (аккаунт) владеет несколькими агентами — ИИ-продавцами, у
каждого своя база знаний, воронка заказов и статистика. Общий обзор, команды запуска и
таблица этапов — в [README репозитория](../README.md).

**В интерфейсе нет ни одной зашитой цифры.** Всё, что видит пользователь — имя компании,
имена агентов, роли, содержимое разделов — приходит с бэкенда. Собранный бандл ничего не
знает про данные клиента.

## Запуск

Фронтенд не работает сам по себе — ему нужны бэкенд из `server/` и база в Docker. Полный
порядок первого запуска — в [README репозитория](../README.md#запуск-локально). Здесь —
только команды самого фронтенда, из каталога `rakurs/`:

```bash
cp .env.example .env.local   # адрес бэкенда, см. ниже
npm --prefix rakurs run dev  # http://localhost:5173
```

```bash
npm --prefix rakurs run build             # tsc + vite build → dist
npm --prefix rakurs run typecheck         # только типы
npm --prefix rakurs run build:standalone  # весь кабинет одним файлом → standalone/rakurs.html
```

Без бэкенда экраны покажут ошибку с кнопкой повтора — это правильное поведение, а не
поломка.

## Подключение бэкенда

```dotenv
VITE_API_URL=/api                       # куда фронт шлёт запросы
VITE_API_PROXY=http://localhost:3000    # куда dev-сервер проксирует /api
```

Прокси нужен, чтобы фронт и API были на одном origin и не пришлось настраивать CORS. В
продакшене то же самое делает nginx — конфиг и инструкция по деплою в
[`deploy/README.md`](../deploy/README.md).

Три вещи, на которых обычно спотыкаются на VPS:

1. **`try_files $uri $uri/ /index.html`** в nginx обязателен. Роутер живёт в браузере,
   без этой строки прямой заход на `/a/:agentId/dialogs` или F5 внутри приложения вернут
   404.
2. **Секреты WhatsApp и Meta — только на бэкенде.** Всё с префиксом `VITE_`
   вкомпилируется в бандл и будет видно в исходниках страницы.
3. **Долгие ответы.** Разбор диалога моделью и синхронизация с Meta займут десятки
   секунд, когда появятся на своих этапах — прокси должен быть готов ждать, а не рвать
   соединение по таймауту.

## Что отдаёт бэкенд

Формы данных — в `@rakurs/contract` (`packages/contract/index.ts`), вызовы — в
`src/api/index.ts`. Всё в JSON; ошибки — обычными кодами HTTP, тело вида
`{"message": "..."}` показывается пользователю как есть.

| Метод и путь | Что отдаёт |
|---|---|
| `POST /api/auth/login` · `POST /api/auth/logout` | сессия по e-mail и паролю; сессия — HttpOnly-кука |
| `GET /api/auth/me` | текущий пользователь и компании, в которых он состоит, с ролью в каждой |
| `GET /api/accounts/:accountId/agents` · `POST /api/accounts/:accountId/agents` | агенты компании; создание — только для владельца |
| `GET /api/agents/:agentId` · `PATCH /api/agents/:agentId` | один агент; имя, описание и часовой пояс меняет только владелец |

Разделы агента — Заказы, Диалоги, База знаний, Агент, Интеграции, Статистика — пока не
отданы бэкендом: каждый экран честно показывает, на каком этапе появится. Настройки —
седьмой раздел — уже реальны. Список этапов — в README репозитория.

## Как устроено

```
src/
├── api/          все обращения к бэкенду: client.ts — транспорт, index.ts — вызовы
├── components/
│   ├── layout/   сайдбар, шапка, каркас экрана агента
│   └── ui/       примитивы, состояния загрузки и пустоты, всплывающие сообщения
├── hooks/        useApi — загрузка с отменой и повтором
├── lib/          список разделов кабинета (sections.ts), форматирование (format.ts)
├── screens/      по файлу на экран: вход, выбор агента, настройки агента, заглушка раздела
├── store/        auth — сессия и вход; agent — текущий агент и роль в нём; app-state — тема
├── styles/       дизайн-токены, шрифты, общие классы
└── types/        `export type * from '@rakurs/contract'` — контракт с бэкендом
```

Действия, меняющие данные на сервере — переименование агента, его создание — ждут ответа;
кнопка на это время блокируется и меняет подпись. Если сервер отказал, введённые значения
остаются на экране и показывается сообщение об ошибке: печатать всё заново — последнее,
что должен делать человек после неудачного сохранения.

## Дизайн-система

Токены объявлены CSS-переменными в `src/styles/tokens.css`: тёмная тема на `:root`,
светлая на `:root[data-theme="light"]`. Светлая — по умолчанию, выбор пишется
в `localStorage['rakurs-theme']` и читается синхронно в `index.html` до первой
отрисовки, иначе видно вспышку светлой темы.

Плоский стиль: теней нет, разделение только границами `1px`. Из анимаций — пульсация
индикаторов активности и мерцание заглушек, обе отключаются при `prefers-reduced-motion`.

Шрифты — Golos Text (интерфейс) и JetBrains Mono (числа, идентификаторы, таймстемпы) —
лежат в `public/fonts` и подключаются из `src/styles/fonts.css`. Оба под SIL Open Font
License 1.1. Локальные файлы убирают запрос к стороннему CDN, снимают мигание текста
при загрузке и делают отрисовку одинаковой в офлайне.

## Что осталось за рамками

- **Мобильная версия.** Кабинет рассчитан на десктоп, брейкпоинтов нет по замыслу —
  разделы проектируются для мобильного экрана заново, когда до этого дойдёт очередь, а не
  сжимаются из текущей вёрстки.
- **Разделы агента.** Заказы, Диалоги, База знаний, Агент, Интеграции и Статистика — пока
  заглушки. Какой этап подключает какой раздел, см. README репозитория.
